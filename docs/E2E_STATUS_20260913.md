# Full TikTok Warm-up + Boost E2E lane — 2026-09-13

## Qualification baseline

Primary qualification device is the GenFarmer #7 Pixel 4 XL lane. The shared feed anchor is ranked candidate 8. It has been proven unique across repeated Pixel hierarchy samples and the one-step warm-up primitive has produced a live `PASS` with `full_selector` verification before and after the swipe.

GenFarmer #1 / TECNO is temporarily excluded from the release gate because repeated TikTok ANR behavior makes it an unhealthy qualification target. This is a device-health issue, not a reason to weaken the app-level correctness gates.

## Full Warm-up controller

`scripts/tiktok_warmup_session.py` composes the qualified one-step primitive into a complete bounded session:

- deterministic/randomized watch-time schedule;
- configurable video count;
- <=60 minute hard cap;
- bounded per-step retries and session failure budget;
- foreground recovery inherited from the one-step primitive;
- selector verification whenever hierarchy is healthy;
- explicit degraded foreground-continuity evidence if the hierarchy helper is unavailable;
- checkpoint after every completed video;
- resume support;
- rest-only sessions;
- action/evidence summary without engagement actions.

`scripts/tiktok_warmup_preset.py` makes saved JSON presets executable. Example presets live in `config/tiktok-warmup-presets.example.json`.

## Full Boost controller

Boost is account-local and requires an explicit ready gate. No likes, follows, replies, DMs, or coordinated engagement are implemented.

`scripts/tiktok_boost_explore.py` supports keyword, hashtag, account and link exploration using runtime hierarchy-derived controls or an explicit Android VIEW intent for links.

`scripts/tiktok_boost_publish.py` implements the write path:

1. hash the explicitly approved local media;
2. reject previously published hashes by default;
3. stage the exact file into a dedicated device folder;
4. resolve its exact Android MediaStore content URI;
5. target TikTok with that exact URI instead of guessing a gallery tile;
6. advance through fresh hierarchy-derived exact Next/Continue controls;
7. optionally enter a conservative ASCII caption;
8. require an exact Post/Publish/Post now semantic match for the final write action;
9. require both `--apply` and `--publish` before the final tap;
10. mark the media as published only after the qualified feed selector returns.

`scripts/tiktok_boost_session.py` composes optional Explore + Publish into one end-to-end run. Saved Boost presets are supported by `scripts/tiktok_boost_preset.py` and `config/tiktok-boost-presets.example.json`.

## Release acceptance

Warm-up is considered fully qualified on a device only after a multi-video session completes with checkpoint/evidence and without unbounded retries. Boost publish is considered fully qualified only after an approved disposable test media item reaches `PASS_PUBLISHED`, duplicate history is persisted, and the feed-return selector proves the app returned to a known safe state.

The next scaling phase is separate: repeat the same exact E2E qualification across additional healthy devices, then add XProxy readiness and multi-device scheduling. Do not let an unhealthy single phone block application-level development.
